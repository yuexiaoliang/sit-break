# 日程设置交互原型

这是 `codex/prototype-round-schedules` 分支上的一次性原型，用于确认：**如何保留简单计时，同时让需要详细安排的人按需设置时段和轮次？**

用户已确认 A · 时段卡片结构，并选定「节奏优先」视觉方向。当前只保留这一方案；旧布局、方案切换条和数据调试面板均已删除。

关联规格：[按轮次推进的自定义日程与休息安排 #1](https://github.com/yuexiaoliang/sit-break/issues/1)。

## 启动

首次检出后安装依赖：

```bash
npm ci
```

启动预览：

```bash
npm run prototype:schedule
```

[简单计时](http://127.0.0.1:1421/settings.html?prototype=schedule) · [日程安排](http://127.0.0.1:1421/settings.html?prototype=schedule&mode=schedule) · [深色预览](http://127.0.0.1:1421/settings.html?prototype=schedule&theme=dark)

只在开发环境显式指定 `prototype=schedule` 时加载。数据保存在内存中，刷新恢复示例。旧链接中的 `variant` 参数会自动移除，仍进入已确认的界面。

## 简单计时与日程共存

默认显示工作、休息时长及快捷数值，一组时长反复提醒。「使用日程」默认关闭；开启后显示时段卡片，关闭后恢复简单时长。两种配置分别保留，单轮展开状态也会保留。

所有页面共用最大 562 CSS px 的窗口，开启或关闭日程不改变宽度、居中位置；日程内容向下展开；当天概览改为标题旁的「预览日程」按钮，按需打开浮窗，不占用设置页空间。窄屏时窗口随可用空间缩小，内容纵向滚动。

语言、提示音、开机自启、离开自动重置和提醒小字共用。Windows 另外显示悬浮计时条开关与大小；macOS 展示菜单栏预览。

## 日程编辑

像手机闹钟一样选择每周重复或仅一次。每个时段设置开始/结束时间和默认工作/休息时长，按需展开单轮调整。休息内容自由输入一项或多项活动，整次休息共用一个倒计时。

预览浮窗只读，列出当前草稿的时段、空档、首次预计休息和特殊轮次，并说明时间可能顺延。预览不保存修改或启动计时；可用关闭按钮、Esc 或点击外侧返回编辑，保留草稿、展开状态和焦点。长内容在浮窗内滚动，标题与关闭入口固定可见，支持键盘滚动。到点先提醒；用户可「再等等」或「开始休息」。晚开始仍计满休息时长，后续轮次顺延。

## 外观与演示工具

默认跟随系统明暗外观，系统变化时立即更新。窗口外的「外观」选择器可切换跟随系统、浅色、深色，用于设计预览；`theme=light` 或 `theme=dark` 可直达对应主题。

切换主题不重建表单，也不重置草稿、单轮展开状态或试运行进度。输入、下拉菜单、原生时间控件、保存反馈及所有运行状态使用一致的主题变量。

窗口外只保留外观、平台和试运行控件，供设计与规则验收使用。正式产品保留只读日程预览，不提供试运行、时间推进或情景模拟入口。

## 建议试用过程

1. 调整简单时长和提醒小字，开启再关闭日程，检查窗口不变宽且输入仍保留。
2. 开启日程，点击标题旁的「预览日程」查看安排，再关闭浮窗继续编辑。展开上午的单轮安排：第一轮工作 50 分钟、爬楼 10 分钟；第二轮工作 55 分钟、深蹲 5 分钟。
3. 输入多行活动，切换浅色与深色，确认内容和展开状态保留。
4. 试运行「晚 5 分钟才开始休息」：09:55 开始，仍休息 10 分钟，预计 10:05 进入第二轮。
5. 休息中暂停、切换主题、推进模拟时间，确认剩余时长保持；午休边界仍允许已开始的休息完成，再待机。
6. 用窗口外的平台预览检查 Windows 的悬浮计时条设置；用窄窗口检查控件是否可访问。

模拟日为 2026-10-14（周三）；下午结束时间 18:00 是可修改的示例值。
