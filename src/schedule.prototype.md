# 日程设置交互原型

这是一次性原型，保存在 `codex/prototype-round-schedules` 分支，用于回答：**如何保留现有简单计时，同时让需要详细安排的用户按需设置日程和单轮调整？**

关联规格：[按轮次推进的自定义日程与休息安排 #1](https://github.com/yuexiaoliang/sit-break/issues/1)。

## 启动

首次检出该分支后安装依赖：

```bash
npm ci
```

启动原型只需：

```bash
npm run prototype:schedule
```

打开 [简单计时原型](http://127.0.0.1:1421/settings.html?prototype=schedule&variant=A)，默认关闭“使用日程”。需要直接查看详细安排时，打开 [方案 A 的日程界面](http://127.0.0.1:1421/settings.html?prototype=schedule&variant=A&mode=schedule)。

原型嵌入现有设置页，只在开发环境且显式指定 `prototype=schedule` 时加载；数据全部保存在内存中，刷新即恢复示例。

## 简单计时与日程共存

默认页面直接显示工作时长、休息时长及快捷数值，保留一组时长反复提醒的使用方式。“使用日程”作为可选入口，开启后展开详细安排，关闭后回到原来的简单时长；两边的配置分别保留。

提示音、开机自启、离开自动重置、语言和自定义提醒小字由两种方式共用。Windows 另外显示悬浮计时条开关和大小；macOS 沿用菜单栏，不增加悬浮球设置。页面外侧的系统切换按钮只是原型预览工具。

两种方式均可试运行，演示提醒、再等等、开始休息、暂停、重置和提前结束。简单计时使用共用提醒小字，日程中填写的本轮内容优先，未填时也使用共用小字。

## 三种方案

| 方案 | 操作结构 | 值得观察的取舍 |
| --- | --- | --- |
| A · 时段卡片 | 每个时段设置默认工作/休息时长，按需展开单轮调整；旁边显示一天概览 | 常规设置集中、特殊设置收起；时段较多时页面会较长 |
| B · 一天时间线 | 先看一天的工作和空档，点击时段，在旁边调整 | 全天关系直观；编辑时需要在时间线与详情间切换注意力 |
| C · 分步设置 | 依次选择日期、时段、单轮安排，最后确认概览 | 每一步信息少；熟练用户回改多个内容时步骤较多 |

三种方案只比较日程编辑结构，默认的简单计时界面相同。同一路由使用 `variant=A`、`variant=B`、`variant=C` 切换。底部浮动条和左右方向键都可切换；输入框、文本框和下拉菜单里的方向键保留原用途。切换布局保留本次编辑的数据。

页面外侧的“查看原型数据”包含当前方案、简单时长、通用设置、编辑中的日程、已保存的模拟日程与运行进度，便于核对每次操作。

## 建议试用过程

1. 默认使用简单计时，把工作设为 30 分钟、休息设为 3 分钟，填写提醒小字，试运行一次“提醒 → 再等等 → 开始休息 → 下一轮”。
2. 返回设置，开启“使用日程”。在 A 中展开上午的单轮安排：第一轮为工作 50 分钟、爬楼 10 分钟；第二轮为工作 55 分钟、深蹲 5 分钟。
3. 修改日程名称，再关闭“使用日程”，检查简单时长、日程草稿及通用设置都保留。重新开启后仍能继续编辑。
4. 日程试运行选择“晚 5 分钟才开始休息”：09:55 开始爬楼，仍休息 10 分钟，10:05 进入第二轮。
5. 进入午休边界情景，推进 5 分钟：11:58 已开始的休息到 12:03 完成，然后待机；推进到下一时段，13:30 从下午第一轮开始，工作 60 分钟再休息 5 分钟。
6. 按需比较 B、C，或用页面外侧的系统预览切换检查 Windows 悬浮计时条、大小设置与 macOS 菜单栏入口。

模拟日为 2026-10-14（周三）；下午结束时间 18:00 是可修改的示例值。

## 当前观察

用户反馈“方案 A 不错”，同时指出旧原型没有完整融入现有功能，现版本应作为简单模式供不需要详细日程的人继续使用。本次以 **A 为基础继续调整**，将“默认简单、日程可选、通用设置共用”落实到原型和规格。

这一反馈确定了简单模式必须保留，并不代表用户已确认所有界面细节，也不授权开始正式功能实现。B、C 暂留作比较依据。

本轮完成前端构建和浏览器操作检查：默认简单模式、30/3 简单计时循环、暂停冻结、保留两种配置、共用小字和声音状态、Windows 96 px 悬浮预览、日程 09:55–10:05 完整休息、12:03 待机及 13:30 重新开始。两种设置页在 390 px 宽度下无横向溢出。生产构建不包含原型界面和切换条。上一轮已检查 A/B/C 切换、单轮编辑和输入时保留方向键。

## 范围与后续处理

此原型不连接真实 Tauri 设置、提醒窗口、系统空闲检测或持久化。声音、开机自启、离开自动重置和语言控件只演示设置状态，不改变电脑配置、不播放声音，也不切换整页文案语言；Windows 与 macOS 外观均为网页模拟。退出恢复、真实休眠及完整跨日行为仍以规格为准；此处只使用内存提示列表和按分钟推进的演示时钟。

原型遵循一次性代码约束，没有新增测试框架或业务测试。选定方案后，将确认的界面决策写回规格，正式实现按规格重新组织并验证，保留本分支作为设计依据。
