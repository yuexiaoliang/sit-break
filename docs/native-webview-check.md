# 本地文件动作指引的原生验收

当前范围按 [ADR 0008](adr/0008-local-files-only-guidance.md) 收紧为从系统文件选择器导入本地视频或单文件 HTML。在线地址、直接选择内置指引与 HTML 源码输入均已移除；此前在线版本的报告与截图不作为当前版本的验收结果。

## 自动化检查

Windows 独立工作流构建并运行真实 exe，经 WebView2 调试接口检查产品实际页面、公开命令及持久化文件。专用标识为 `com.sitbreak.nativecheck`，必须使用全新的数据目录，不能删除已有用户设置来重试。工作流上传截图、应用日志和 `report.json`。

- 从真实保存的日程进度缩短工作等待，再经产品恢复入口触发提醒，核对文字、倒计时、系统主题、紧凑窗口、退出恢复与提前结束。
- 简单计时实际等待一分钟，播放已导入视频副本，检查静音循环、播放／暂停／进度、主题及 tick 保留、计时独立与结束释放。
- 视频副本验证受控协议、HEAD／Range、当前轮替换保留、退出恢复旧引用和下一轮新引用。
- 单文件 HTML 验证内嵌图片、脚本、动画、页内滚动和主题保留；通过本机受控 HTTP 样例确认远程图片、嵌套页面和外部导航没有请求到服务器。
- 能力样例实际尝试应用命令、设置修改、确实存在的文件和资源读取，核对宿主设置、当前轮及计时保持。
- 作者材料检查文件选择选项仅有“不使用、本地视频、本地 HTML”，指引区域没有网址或 HTML 源码输入框；提示词仅供只读查看和复制。示范 HTML 按本地副本路径验证交互、配色、内容保留和销毁。

媒体原生自动化使用明确标记的 `preimported-copy` fixture，预置格式与真实导入副本一致，但没有操作原生文件选择器，不能作为选择文件和导入命令的端到端证据。实际文件复制、删除源文件、替换／移除和保留引用另由 Rust 资源入口测试覆盖。

报告中各模块的 `status` 才表示对应执行结果。构建、脚本存在和其他版本的通过结果均不能代替本次原生结果；当前分支运行及源提交见 [PR #26](https://github.com/yuexiaoliang/sit-break/pull/26)。

## macOS 与手动交互的范围

macOS 本机的原生界面控制连接持续超时。独立测试包构建和磁盘映像校验只能证明打包成功，本次尚未将 WKWebView 播放、导入、主题和交互记为通过。

发布前仍需完成：

- [ ] macOS：本地视频和 HTML 的实际播放／交互、系统亮暗、退出重开和紧凑浮窗。
- [ ] macOS 与 Windows：从系统文件选择器导入 MP4 和 UTF-8 HTML；取消或失败保留旧配置，源文件移走后继续展示，替换和重开保持正确。
- [ ] macOS 与 Windows：实际复制完整提示词，保存示范与模板，再从文件选择器导入导出的 HTML；保存取消不显示成功。
- [ ] macOS 与 Windows：纵向视频、长文字、长 HTML 和较小屏幕下内容可读、内部滚动，倒计时和结束按钮始终可见。

## 本机运行

Windows 需要 Node 22、WebView2 Runtime、图形会话和干净的测试用户。创建独立标识的 Tauri 配置后运行：

```powershell
npm run tauri build -- --debug --no-bundle --config "$env:TEMP/sit-break-native-check.json" -- --locked
node scripts/native-webview-check.mjs src-tauri/target/debug/sit-break.exe .scratch/native-webview-check
```

脚本会临时切换测试用户的应用亮暗主题，在结束时恢复原值。调试端口仅存在于 Windows debug 构建，发布构建不包含此入口。测试不关闭浏览器安全策略，不覆盖所有视频编码、显示缩放或物理睡眠场景。
